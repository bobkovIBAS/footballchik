# Football Simulator («Набивай!»)

Футбольный симулятор для Roblox: набивайте мяч, улучшайте бутсы, подписывайте футболистов и пробивайте по воротам. **Локальная контрольная копия — [`fotball-integrated.rbxl`](fotball-integrated.rbxl).** Текущая разработка идёт в приватном облачном Football Simulator через Team Create. Он содержит новую карту, UI V2, игровые механики, экономику, прогрессию и код сохранений. `fotball` в облаке и прежние файлы карты и предпросмотра — архивные версии.

## Что есть в игре

- **Футзал.** У общего мяча `G` начинает и завершает свободное набивание, `E` выполняет удар. `F` запускает тренировку ритма после первого контракта и трёх золотых ударов. Свободный режим даёт монеты, ритм — тренировочную силу. На мобильном используйте экранные действия.
- **Основное поле.** У мяча перед восточными воротами первое `Q` запускает шкалу мощности, второе выполняет удар. HP, уровень ворот и награда персональные. Западные ворота декоративные.
- **Магазин и Академия.** Монеты расходуются на бутсы, улучшения золотого мяча и контракты. Команда даёт пассивный доход, а Академия объединяет состав, задания дня и финты. Дивизионы отражают прогресс коллекции.
- **Карта и UI V2.** Центральная площадь соединяет Академию, стадион, футзал, магазин бутс и зоны порталов. UI V2 по умолчанию показывает монеты, силу, золотую шкалу, контекстные действия и меню «Бутсы», «Команда», «Прогресс» и «Настройки».

## Открытие, проверка и сохранение

1. В Roblox Studio выберите **File → Open from File** и откройте `fotball-integrated.rbxl` из `FootballIntegration`. Если он уже открыт, используйте это окно. Локальный файл имеет `PlaceId = 0`; для обычного запуска Rojo и сборка не нужны.
2. Запустите **Play** с одним персонажем. Проверьте старт на площади и HUD, оба действия у мяча на футзале, стойку магазина, точки Академии и удар по восточным воротам. Посмотрите **Output**. QA запускает **Server & Clients** или **Team Test** только по явному запросу на мультиплеер. Координаты и прошлые результаты есть в [INTEGRATION.md](INTEGRATION.md).
3. Локальный Play использует профиль в памяти; прогресс пропадает после остановки. Облачные данные не входят в `.rbxl`. Не включайте доступ Studio к API и не меняйте режим сохранений для обычной проверки. Для тестов общих правил запустите `luau tests/club_rules.luau` и `luau tests/goal_rules.luau`.
4. Постоянные правки сохраняйте в Edit в облачном Place. Для автономной проверки открывайте локальную контрольную копию. Перед крупной правкой сделайте контрольную точку, а изменённые скрипты вручную сверяйте с `src/`.
