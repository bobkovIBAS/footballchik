# Архитектура Football Simulator

Контрольная локальная сборка — [`fotball-integrated.rbxl`](../fotball-integrated.rbxl). В ней постоянная карта и скрипты, достаточные для открытия в Studio. Постоянные изменения вносятся в [облачный Place](TEAM_CREATE.md). Это Luau и стандартные Roblox Services. Автоматического обмена с `src/` или общим Place нет.

| Локальные файлы | Ветки Edit и ответственность |
| --- | --- |
| `src/server/` | `ServerScriptService.JuggleServer`: `Main` запускает серверный цикл и проверяет запросы; `IntegratedMap` и `Pitch` соединяют сцену с механиками; `GoalShot` обслуживает удар по воротам; `Profiles` отвечает за загрузку и сохранение. |
| `src/shared/` | `ReplicatedStorage.Juggle`: `Balance`, `ClubRules`, `GoalRules`. Сервер создаёт `Action`, единый RemoteEvent для запросов и подтверждённых снимков состояния. |
| `src/client/` | `StarterPlayer.StarterPlayerScripts.JuggleClient`: `Main` запускает V2, оставляет V1 для локального сравнения; `UIV2.Session` обрабатывает снимки; `Effects`, `KickMotion`, `GoalView` рисуют подтверждённые действия и персональные ворота. |
| Геометрия в `.rbxl` | `Workspace.HubLayout` и `Workspace.FootballAcademyDesign` содержат визуал. `Workspace.FootballCampus` с атрибутом `IntegratedLayout` содержит игровые привязки. Точные точки — в [INTEGRATION.md](../INTEGRATION.md). |

Сервер контролирует профиль, дистанцию, доступ к тренировке, владельца мяча, темп запросов, выдачу наград и HP ворот. Отображение на клиенте не изменяет серверное состояние. У футзального мяча два режима. На стадионе используется один мяч по очереди; уровень и HP восточных ворот принадлежат конкретному игроку.

В обычном Play данные живут в памяти. За пределами Studio профиль хранится в `Juggle_v1` по ключу `user_<UserId>` в пределах своего Experience. В коде есть отдельная ветка `JuggleStudio_v1`, выключенная текущей настройкой. Не меняйте экономику, схему профиля и режим доступа к API без отдельной задачи. См. [Team Create и сохранения](TEAM_CREATE.md).

Манифесты Rojo задают соответствие между папками и деревом скриптов. Lune используется для анализа и реконструкции контрольных копий. Обычный запуск Place этих инструментов не требует. Правила переноса — в [AGENTS.md](../AGENTS.md).
